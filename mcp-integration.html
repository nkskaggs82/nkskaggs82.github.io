Salesforce + AI via MCP:
running an org from a chat window

I connected a Salesforce org to AI tools (Claude, Claude Code and Cursor) through Salesforce's hosted MCP servers, part of Salesforce AIforce (formerly Headless 360). Now a person can ask the org a question, update a record, or run an AI template just by typing a sentence, and Salesforce's own security still decides what they can see and change.

The problem

Getting answers out of Salesforce takes too many steps

Simple questions and small updates add up. In a call center they happen hundreds of times a day, and each one means a report, a search, or a few minutes of clicking.

Before

A supervisor wants to know which customers' promotions end this month. They request a report, wait for it, export it and sort it in a spreadsheet.

A rep needs to escalate a case. They open the case, change the status, then type a note.

After

The supervisor types "Which customers' promotions end this month?" into an AI chat tool like Claude. The list comes back in seconds, with no report.

The rep types "Escalate case 00001080 and note that the customer called back." The case updates without being opened.

Both still follow Salesforce security: each person can only see and change what they already could in Salesforce.

In plain English

Two ideas behind it

MCP: a universal plug for AI

Model Context Protocol is an open standard that lets any AI tool connect to a system like Salesforce in the same way. Think of it as USB-C for AI: set up the connection once, and Claude, Cursor or another AI tool can all use it.

AIforce: Salesforce without the screens

Salesforce announced this as Headless 360 in April 2026 and renamed it AIforce in September 2026. It opens Salesforce's data, actions and rules to AI tools through MCP and APIs. People can work from chat, Slack or Copilot, while the data and the security rules stay in Salesforce.

Fix data by describing the change

The package pricing in my mock org needed updating to line up with the DIRECTV-style pricing the org is modeled on. Instead of editing records one by one, I gave Claude the pricing structure and had it make the change through MCP.

Security

The org stays in charge

Every call goes through OAuth as a real Salesforce user, so that user's profile, permission sets and sharing rules decide what the AI can see and change. The External Client App only grants the scopes MCP needs. The servers are switched on one at a time in Setup. Salesforce also offers a write server without deletes (SObject Mutations), which is the safer choice for a production org. I used write access only in my own developer org with mock data.

How it's built

Four pieces

No custom code was needed for the connection itself. It's all Salesforce setup plus each AI tool's connector settings.

What I learned

  • MCP setup is mostly Salesforce admin work: an External Client App, OAuth scopes and turning servers on.
  • Ask for the query along with the answer. It makes the result easy to check.
  • Pick the narrowest server for the job: read-only or no-delete wherever possible.
  • Managing several External Client Apps means keeping callback URLs straight. I ran into conflicts early on.

Next phase

  • A read-only bridge so managers can ask Salesforce questions from Microsoft Copilot without a Salesforce license. I have a proof of concept in Copilot Studio that's waiting on admin approval.
  • A scheduled morning list of customers whose offers end soon, pulled through MCP.
